# 粘性会话（客户端亲和）

**状态：未实现（提案）**

## 1. 设计

**问题**：加权轮询会把同一客户端的请求打散到不同上游。上游如果持有本地状态
（登录会话、内存缓存、上传中的临时文件），跨机器的请求就会失效。

**目标**：给"需要粘性"的路由提供一个亲和键，让同一客户端固定落到同一上游；
**默认关闭**，因为开启后用均衡换确定性。

| 方案 | 适用 | 问题 |
| --- | --- | --- |
| Cookie 亲和（推荐，浏览器） | 页面与接口同源 | 需要签名防伪造；首次请求要种 cookie |
| Header 哈希（推荐，API） | 客户端能带 `X-User-Id` 等 | 必须客户端配合；上游增减会漂移 |
| IP 哈希 | 零配合 | NAT 后大量客户端共用 IP，均衡会歪 |
| 网关会话表 | 精确、可审计 | 失去无状态，要存储与过期清理 |

**结论**：做统一的"亲和键"抽象，支持 `cookie` / `header` / `ip` 三种模式。

## 2. 技术方案

### 2.1 配置

```json
{
  "routes": [{
    "prefix": "/app/",
    "targets": [{"url": "http://127.0.0.1:9001"}, {"url": "http://127.0.0.1:9002"}],
    "affinity": {
      "mode": "cookie",
      "cookie": "ydd_upstream",
      "ttl_seconds": 3600
    }
  }]
}
```

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `mode` | `none` | `none` / `cookie` / `header` / `ip` |
| `cookie` | `ydd_upstream` | cookie 模式的 cookie 名 |
| `header` | — | header 模式的键（如 `X-User-Id`） |
| `ttl_seconds` | `3600` | cookie 有效期与签名过期时间 |

校验：`mode=header` 时必须给 `header`；`ttl_seconds > 0`；与 `health` 一样支持路由级覆盖。

### 2.2 选路顺序

```text
1. 过滤：健康 且 未冷却
2. 读亲和键 → 命中某个可用上游 → 选它
3. 未命中，或命中的上游不可用 → 正常平滑加权轮询
4. 选择结果不是"亲和键指向的上游"时，重签 cookie 并随响应下发：
   Set-Cookie: ydd_upstream=<签名>; Path={prefix}; HttpOnly; SameSite=Lax; Max-Age={ttl}
```

签名内容：`hmac_sha256(secret, "{prefix}|{upstream_url}|{expires}")`。
**不要**把上游索引签进去——上游顺序调整后会指错。

### 2.3 与上游本身的 Set-Cookie 共存

代理已经原样转发上游响应头。实现时注意：

- 响应可能同时有上游的 `Set-Cookie` 与网关的亲和 cookie，**必须合并成多条**，不能相互覆盖；
- 网关 cookie 用独立名字（默认 `ydd_upstream`），避免撞名；
- 只在 `mode=cookie` 时下发；`header`/`ip` 模式不在响应里加任何头。

### 2.4 WebSocket 的限制

WS 握手响应里**无法种 cookie**（响应已升级）。因此：

- `cookie` 模式的 WS：要求客户端先通过一次普通 HTTP 请求拿到 cookie，再连 WS；
- 或该路由改用 `header`/`ip` 模式；
- `accept` 之后不能迁移上游（协议无重放），与现有的连接期切换规则一致。

### 2.5 失效与漂移

- cookie 指向的上游被冷却/不健康 → 忽略亲和，走轮询并重种；
- 上游集合变化（配置改动、重启）→ 签名里的 url 对不上 → 自动重新分配；
- 亲和会削弱均衡：统计上接受倾斜，不要同时开启严格权重预期。

### 2.6 测试

同 cookie 两次请求落到同一上游；无 cookie 时轮询且返回 `Set-Cookie`；
伪造/过期 cookie 被忽略并重种；cookie 指向冷却中的上游时回退；
上游自身的 `Set-Cookie` 不被吞掉；`mode=header` 按 header 分流。

**成本**：约 100 行 + 5 个测试；依赖与 Cookie SSO 共用的签名模块。

## 3. 边界

- 只在单进程内有效（与现有架构一致）；
- 不解决"上游本地状态过期"问题，只保证路由一致；
- 上游有状态本身是架构问题：能改成无状态（共享会话存储）时优先改架构，而不是加粘性。
